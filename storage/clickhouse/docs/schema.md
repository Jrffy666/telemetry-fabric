# ClickHouse Blockchain Schema

This schema stores normalized blockchain events from `contracts/proto/blockchain`
and shared metadata from `contracts/proto/platform/envelope.proto`.

## Tables

| Table | Purpose | Primary contract source |
| --- | --- | --- |
| `chain_blocks` | Canonical and reorged block headers plus block-level metrics. | `ChainEvent` block coordinates, Envelope metadata |
| `chain_transactions` | Transaction-level facts keyed by `tx_hash` and block position. | `ChainEvent` |
| `chain_logs` | Raw log coordinates, topics, data, and normalized event fields. | `ChainEvent` |
| `chain_token_transfers` | ERC/SPL/TRC token movement facts with parsed amounts. | `ChainEvent.TokenStandard` |
| `chain_address_activity` | Batch-produced address rollups for fast wallet views. | Derived from `ChainEvent` |
| `chain_node_health` | RPC endpoint and adapter health samples. | `NodeHealth` |
| `chain_alert_events` | Alert state and history. | `AlertEvent` |
| `chain_reorg_events` | Reorg boundaries and removed/added block arrays. | `ReorgEvent` |
| `chain_discard_metrics` | Drop/discard aggregates from rule matching. | `Envelope`, `FilterRule`, `RuleMatch` |

## Contract Mapping

The following protobuf fields keep their original names in ClickHouse where
possible:

- Chain identity: `chain`, `network`, `chain_id`.
- Block coordinates: `block_number`, `block_hash`, `block_timestamp`.
- Transaction/log coordinates: `tx_hash`, `tx_index`, `log_index`.
- Addresses: `from_address`, `to_address`, `contract_address`,
  `token_address`.
- Token values: `token_symbol`, `token_standard`, `amount_raw`,
  `amount_decimal`, `amount_usd`.
- Runtime status: `gas_used`, `gas_price`, `success`, `finality_status`,
  `confirmations`, `source_rpc`, `reorged`.
- Envelope metadata: `tenant_id`, `source`, `schema_version`, `ingest_time`,
  `trace_id`, `dedupe_key`, `attributes`.

Large numeric values remain strings to preserve the protobuf contract and avoid
precision loss. Analytical decimal helper columns are materialized for selected
fields:

- `amount_decimal_value Nullable(Decimal(76, 18))`
- `amount_usd_value Nullable(Decimal(38, 18))`
- `value_usd_value Nullable(Decimal(38, 18))`

Writers should continue to populate the string fields as the source of truth.

## Idempotency

Most tables use `ReplacingMergeTree(version_column)`.

- Raw event tables use `updated_at` as the replacement version.
- Rollup tables use `metric_version` and include `batch_id` in the sorting key.
- Stable `dedupe_key` values should be generated by writers and kept identical
  on retry.

ReplacingMergeTree deduplication is eventual. Queries that must be correct
immediately after a retry should use `FINAL`, as the templates do. High-volume
dashboards can remove `FINAL` after background merges are known to be timely.

## Writer Normalization

Recommended writer behavior:

- Lowercase EVM-style addresses before insert.
- Keep non-EVM address casing only when the chain family requires it.
- Populate `tenant_id` from the Envelope, not from adapter-local config.
- Use UTC for every `DateTime64(3, 'UTC')` value.
- Insert arrays and maps with JSONEachRow or Native format rather than string
  encoding them.
